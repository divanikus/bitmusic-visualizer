# Roland MT-32

Open a Standard MIDI file (.mid/.midi, formats 0, 1 or 2) with your own compatible
Control and PCM ROMs. Put them in the [MT-32 ROM directory](../packaging/MT32-ROMS.txt)
as `MT32_CONTROL.ROM` and `MT32_PCM.ROM`. Munt recognizes their hashes and checks
that they belong to a compatible pair. Full old/new MT-32 and CM-32L images are
supported; split dumps are not. ROMs are never bundled or downloaded.

The main player's MIDI row offers **Auto**, **General MIDI** and **MT-32**.
Auto routes Roland MT-32 SysEx to Munt and other MIDI to FluidSynth. An arrangement
without identifying SysEx must be selected manually: a MIDI extension or filename
does not reliably identify the intended synthesizer. The engine choice is saved,
and changing it reloads the current MIDI. Selecting the current engine again
preserves playback and position. In MT-32 mode the folder button opens
the ROM directory and the SoundFont selector is hidden. ROM errors occur only
when opening MT-32 music. This backend does not use SF2 banks.

Eight melodic cards and one rhythm card represent musical **parts**, not nine
independent oscillators. They share the original 32 synthesis partials. Munt
handles partial allocation, PCM/synth timbres, ring modulation, program changes,
channel reassignment and embedded SysEx. Busy arrangements can steal partials.
Default MIDI assignment is channels 2–9 for melodic parts and channel 10 for
rhythm; files can change the assignment. GM arrangements need not sound correct
when forced through MT-32.

Parts receiving no notes anywhere in the file start unchecked in the card
editor. The load-time check follows SysEx channel reassignment and device resets,
including changes later in the song, without synthesizing the whole track.
Parts remain available for manual display; audio and part numbers are unchanged.
Grid, preset and reset behavior follows the [MIDI visibility rules](MIDI.md).

Each part has a stereo dry waveform, spectrum, mute and Solo; existing shortcuts
and layout presets apply. Headings show the current patch name (Rhythm for drums),
without resetting the layout on program changes. Overlapping older patches may
still sound. Keyboard shows the active played keys; it does **not** measure patch
transposition, fine tuning, pitch bend or modulation. Rhythm and Full mix retain
the experimental single-pitch audio estimate.

Taps are taken after partial pairing/panning and before shared DAC, reverb and
analogue output. Full mix includes the enabled parts, shared reverb and output
volume/L/R switches. Muting a part gates its new input to the shared effects;
an existing reverb tail can remain. It does not stop envelopes or change the
independent scope signal. One synthesizer renders all nine taps together; there
is no extra instance per card. Audio and scopes have separate worker instances.

File tempo changes, SysEx timing, leading rests and the declared endpoint are
preserved. MIDI tracks are concurrent parts, not playlist songs. At the endpoint
pedals/notes are released, followed by a two-second tail. Play/F7 after the end and
Repeat restart from zero. There is no silence trimming or intro countdown.

Long jumps/rewinds replay control/program/SysEx state and held keys/sustain,
then render up to two seconds of preroll. This is **approximate seeking**:
older held notes restart with the current patch, and old envelope phases or
long reverb tails cannot be recovered exactly. If a file changes timbres or
channel assignments under held notes, a seek can temporarily sound different
from uninterrupted playback. Exact hardware state snapshots are not exposed by
Munt. Seeking is cancellable in both workers. Parsed MIDI and verified ROM bytes
form a shared immutable snapshot; deleting a ROM after load does not break scopes
or rewind. Loading a new file reads the ROMs again.

## Implementation and checks

Munt/libmt32emu 2.8.3 is static, with the Float renderer, 32 partials and COARSE
32 kHz analogue output. A shared 64-tap, 128-phase windowed-sinc resampler converts
master and part lanes to 44.1 kHz, adding about 1 ms of delay. SMF timestamps are
scheduled directly; extra serial MIDI cable delays are disabled. Munt's internal
event/partial-stealing delays still apply. There is no OS MIDI driver dependency.

The hash-pinned [LGPL patch](../native/munt-taps/README.md) exposes dry part samples
and gates, and gives each synth its own deterministic pitch-timer jitter instead
of libc's global random generator. This preserves audio/scope synchronization.

The shared parser accepts one used MIDI output port, including a nonzero port
number; empty tracks' prefixes do not create extra outputs. Unaddressed conductor
SysEx follows that output. Conflicting explicitly addressed outputs are rejected.
The other [SMF limits](MIDI.md#limits) apply. Standalone SysEx, XMI/RMID and live
MIDI input are not included in this increment.

Run `bitmusic_checks --mt32-checks <output-directory> --decoder-only` for
ROM-free selection, persistence and missing/invalid ROM checks. Add
`--roms <directory>` containing the named pair for nine-part isolation, mute,
capture transparency, chunk invariance, cold rewind, snapshots, cancellation and
long seek checks. Omit `--decoder-only` for muted live playback/transport/scopes.
Optional `--midi <path>` checks a local arrangement read-only, including distant
seeks; test copies/settings are isolated. Generated MIDI contains no game music.
Hosted CI runs the ROM-free checks; real synthesis requires your own ROMs.
